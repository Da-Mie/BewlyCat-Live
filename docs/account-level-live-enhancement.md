# 账号等级过滤与直播间设计

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `utils/accountLevelFilter.ts` | 规范化等级规则、判断账号身份、合并与限流身份查询 |
| `composables/useAccountLevelFilter.ts` | 普通页面响应式判断及 MAIN 世界身份桥接 |
| `inject/accountLevelFilter.ts` | 原生评论 render 入口过滤及空楼层收起 |
| `utils/commentTreeProjection.ts` | 保留原树数据，生成可见评论与提升后的父子关系 |
| `contentScripts/liveLauncher.ts` | 原版直播页的默认跳转与手动入口 |
| `background/liveClient.ts` | 直播接口白名单、登录凭据、请求头和消息发送 |
| `background/liveCommerce.ts` | 房间礼物与 SC 档位、金额确认、单次支付及账号校验 |
| `live/` | 扩展内直播页面、播放、聊天连接、过滤队列与设置 |

原版直播页只加载专用入口脚本，不注入主站完整样式、加载遮罩或 MAIN 脚本。新版页面不搬动原站节点，不改写原站 WebSocket、fetch 或 XMLHttpRequest。

## 等级规则

评论、普通投稿视频卡片和直播消息分别配置。普通视频弹幕没有等级过滤规则或网络拦截器。直播 UL、粉丝牌、财富等级和大会员身份不作为账号 LV。

硬核会员只依据明确的 `is_senior_member` 或 `level_info.identity` 标志。缺少硬核标志的 LV6 使用未知身份策略，不直接归入普通 LV6。本人、关注用户和指定 UID 的豁免仅作用于等级规则。

身份查询按 UID 合并，最多并发 3 个、启动间隔至少 200ms、待处理上限 128、缓存上限 1000。查询失败使用短期未知缓存；所有写入路径执行相同容量限制。切换账号时结清未开始的旧任务，在途旧结果不能回写新缓存。

## 渲染前投影

原生评论在叶子 render 入口判断，未允许的正文、头像和操作不进入渲染结果。没有可见内容的楼层一起收起。动态评论和视频网格先生成展示列表，再创建具体内容。

过滤不修改原始评论对象、ID、分页依据、跨页关系或折叠状态。隐藏父评论时，可见后代提升至最近的可见祖先，重算缩进与分支；缺失或隐藏父节点的摘要不会重新暴露被过滤内容。异常循环关系不会造成可见评论丢失。

视频身份待查时使用普通骨架；只查询加载窗口中的作者。整页都被过滤时停止自动追页，保留通用的手动加载入口。

不创建屏蔽占位、提示、计数、恢复按钮或屏蔽日志。原始业务数据与身份缓存不另行归档为屏蔽记录。

## 直播与原版导航

数字房间链接默认在当前标签页进入扩展页；非房间页面保留原站。明确打开原版的链接和浏览器后退 / 前进不再次自动跳转。关闭默认新版开关后，原版页面仍保留手动入口。跳转失败不阻塞原版页面。

后台仅接受独立直播页的固定操作。Cookie 与 CSRF 留在后台；前端取得的 UID、buvid 与聊天 token 仅用于当前会话。发送请求核对预期账号，且仅由用户点击或提交输入框触发，不自动发送或本地伪造成功消息。

## 播放、聊天与过滤

播放明确请求 AVC，优先 HLS，保留 FLV 与多条 CDN 线路。HLS / FLV 库按需载入，延迟导入后核对播放器代次。线路失败依次回退；全部失败后由用户刷新获取新地址。播放器的自带全屏按钮使用容器全屏，包含自有弹幕层。

聊天使用独立认证、心跳、zlib / Brotli 解码和有上限的重连。身份查询与界面判断不阻塞认证和心跳，聊天错误不覆盖已获取的播放源。切换房间或账号时，旧请求、旧连接和旧发送结果不得改变当前房间状态。原先受限的房间刷新为可用后会重新初始化聊天。

原版屏蔽设置通过 `/xlive/web-room/v1/index/getInfoByUser` 的 `shield_info.keyword_list` / `shield_user_list` 读取，前后核对账号，只向前端返回必要字段。词按区分大小写的字面包含匹配，UID 精确匹配；不扩展为正则或账号等级规则。

进入房间、账号变化及返回页面时同步原版规则，也可手动同步。规则只保留在内存。读取期间最多保留 256 条未决候选，成功后统一过滤并按序交付；失败则清空候选并暂停消息显示。有效规则未变时保留聊天位置和飘屏状态，变化时移除不允许的消息。等级规则调整会重建展示队列并重读历史消息。入场消息在异步身份查询后再次核对显示开关。旧启动快照缺少等级字段时保留未知状态，等待完整设置，避免提前按未启用处理。

聊天列表上限 400 条，飘屏上限 80 条。飘屏按动画结束事件回收；系统减少动画偏好生效时停止飘屏。组件卸载时释放连接、监听器、计时器和未启动的身份查询。

## 礼物与醒目留言

礼物面板读取当前房间可用的普通礼物和 SC 档位，价格、数量上限及字数限制以服务端返回为准。盲盒、大航海等需要专用协议或确认流程的商品不混入普通送礼入口；活动、背包和充值仍使用原版入口。

确认页展示主播、房间、礼物、数量、留言和金额。后台生成绑定页面、房间与账号的短期确认令牌，提交前重新读取礼物价格并核对主播；令牌提交一次即失效，同一账号不能并行支付。Cookie 与 CSRF 不进入界面，支付不自动重试，也不通过本地插入消息伪造成功。SC 区分已发送、待审核和结果不明；网络错误后提示先核实结果。

SC 与礼物沿用原版词 / 用户屏蔽和账号等级过滤，允许后才进入展示模型。SC 保留金额、服务端有效期和消息 ID，悬浮区最多展示最近 3 条有效留言，活动列表上限 20 条；撤回事件同时清除排队项和已展示内容。首次加载时的有效 SC 也走同一过滤队列，不留被过滤消息副本。

普通礼物的文字消息和动效独立控制。动效使用礼物资源图与轻量动画，同时最多 3 条，结束后回收；不加载原站完整活动脚本，也不宣称复刻全部原生礼物特效。SC 悬浮卡片与普通弹幕开关独立，播放器容器全屏包含这些展示层。

## 设置与界面

通过已有设置协调器保存观看偏好，合并防抖写入并在离开时刷新。保存清晰度、线路标识、音量、静音、弹幕、聊天栏和顶栏状态，不保存播放签名地址、房间历史或聊天消息。自动降级和线路回退不覆盖手动偏好。

观看记忆关闭后不保存新选择，下次使用默认值；等级规则与主题独立保存。恢复有声状态后若浏览器阻止自动播放，显示显式播放按钮。

设置弹窗复用共享图标、液态分段指示器和 modal / fade 过渡。原生 dialog 的关闭在退出过渡后完成；快速关闭、重新打开及过期 close 事件均核对代次。主设置分类保留独立选中状态、页面标识和滚动区层级。

使用 `room_info.background` 中的主播背景，不额外读取或解析专题页，也不用视频封面替代。背景仅允许 B 站 CDN 的 HTTPS 图片，柔化与主题遮罩只作用于背景，文字区域保留实色表面；图片缺失或加载失败时回退到主题底色，也可在设置关闭。直播界面的版本标记已移除，扩展清单保留浏览器必需的版本元数据。

界面采用共享排版、间距、圆角与动效 token。文案使用自带四种语言资源，未设置语言时按浏览器选择。界面控件使用 `translate="no"`，房间标题和用户消息另允许翻译。弹幕开关使用 B 站原生开 / 关 SVG 图形，保留开关、D 键和独立聊天栏的语义；许可副本随 assets 打包。

## 构建与验证边界

直播样式仅提取其导入模块，避免引入主站无关样式。生产构建不回写自动导入声明；第三方许可按入口生成，“关于”页同时加载 content、inject、background 和 live 清单。brotli 1.3.3 的 npm 包缺少独立许可文件，构建使用随 assets 保存的包声明、MIT 文本和解码器 Apache 通知补齐展示。

针对性检查覆盖等级 / 硬核身份、评论树投影、原生 render 拦截、视频导航、默认直播导航、设置记忆、消息 FIFO、账号与房间竞态、弹窗生命周期、播放器回退及资源释放。检查使用实际源码与内存服务 / 调度适配器，不创建模拟网页，不向真实账号发送消息。

代码与状态检查不能替代浏览器实机验收。首发以 Chrome / Edge 预发布为目标；Firefox 的构建检查和实机兼容性分开记录。普通礼物和 SC 的发送链路使用隔离接口适配器验证，不执行真实消费；实际账号支付、审核与推送仍需维护者手动验收。直播首页与账号中心及其子页本轮不做适配。
