## 发布步骤

1. 审核 README、更新说明、仓库名和预发布范围。
2. 创建或连接个人 Fork；核对上游、目标分支和当前远端提交，避免覆盖已有工作。
3. 在功能分支整理提交，保留上游历史、版权与许可；通过 PR 合入个人仓库的主分支。
4. 等待该提交的 CI 检查通过，核对源码与审核材料一致。
5. 在主分支手动运行 Release 可生成草稿；需要公开预发布时，从已通过检查的提交显式创建 `release/v1.8.2-personal.1` 分支。版本、仓库地址、已有标签或更新说明不匹配时停止。
6. 工作流重新执行静态检查、构建并验证安装包根目录、版本、名称、主页与独立直播资源，生成包含许可的安装包和 SHA-256，然后创建对应标签与 Release。
7. 浏览器实测覆盖进入 / 返回原版、播放回退、聊天、D 键、设置分类、偏好恢复、过滤与评论树；普通弹幕、普通礼物与 SC 的真实发送、金额扣除、审核 / 撤回、账号风控提示须由维护者手动验收。未完成的检查在预发布说明中披露；本地检查不消费真实余额。Firefox 安装包待实机验证后再提供，商店发布另行安排。

完整浏览器实机回归尚未执行，不能据逻辑检查宣称所有原有功能完全无冲突。首发按预发布提供并披露这一限制；转为稳定版前完成上述关键路径验收。其他尚未覆盖的浏览器与上游功能应在发布说明中如实记录。

## 失败处理

构建、CI 或资产校验失败时保留草稿，不公开发布。若公开后出现阻断观看或原有功能的回归，将该版本标为不推荐使用、提供上一个可用版本和原版直播间入口，修复后发布递增版本；不覆盖已公开标签或悄悄替换安装包。

## 上游维护

不启用新增的自动更新、定时同步或自动合并流程。后续同步上游时手动合并，并检查账号过滤、评论树、设置存储、直播播放和付费交互。版本号跟随上游发布版，本分支修订由 Git 提交与发布说明区分。
